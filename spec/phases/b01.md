## Scope

- [x] Implement accounts, booked/available balances, reservations, balanced immutable postings, statements and operation lookup.
- [x] Implement atomic hold consumption, stable operation IDs, unique constraints, reversals and suspense/settlement accounts with balanced opening fixtures.
- [x] Persist Core Banking posting events in a local journal/outbox; publication is connected in B03.

Expected artifacts: backend/internal/corebanking/; core-banking-service; Core Banking migrations/contracts/fixtures.

Outside this phase: No payment orchestration, FX, fees, overdrafts or complete finance general ledger.

Dependency plan: pin `github.com/jackc/pgx/v5` for PostgreSQL access and `sqlc`
for generated, type-checked queries. Introduce the OpenTelemetry Go SDK plus
maintained HTTP/PostgreSQL instrumentation in the shared runtime. Transactions,
posting rules, idempotency and accounting invariants remain project-owned.

## Exit criteria

- [x] Accounting scenarios A–E have balanced postings and correct balances; original entries remain immutable.
- [x] Concurrent reservations cannot overspend; a lost reply and duplicate operation produce one effect; conflicting operation payloads are rejected.
