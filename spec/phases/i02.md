## Completion handoff

I02 delivers a repeatable local dependency stack and isolated application database
ownership. From a clean checkout run `make infra-init infra-up`, followed by
`make db-provision db-migrate db-seed`. Existing volumes follow the same sequence
without reset. The runbook documents endpoints, credentials, readiness, recovery,
seeding, verification and the separate `make infra-reset CONFIRM=delete-gtb-data`
operation. `make infra-verify` and `make infra-restart-check` are the local
infrastructure checks; the new CI workflow runs these same commands.

I03 can rely on PostgreSQL owner databases with empty `app` schemas, versioned
migration scaffolding, Temporal namespace `gtb`, persistent Kafka, and Keycloak
at `http://localhost:8080`. Each service must use its own database credentials;
never wire applications with `gtb_admin`. Temporal/OIDC schema management remains
with their upstream tools. The Keycloak master realm exists, but GTB identities,
clients and service authorization are not yet configured. No application API or
financial behavior is claimed. All I02 exit criteria have recorded local evidence;
hosted CI remains unobserved.
